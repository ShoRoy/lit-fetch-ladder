# Contributing

Issues and pull requests are welcome, except for the security-sensitive parts, which only the author
changes: the guard, the browsers and the sign-in, the agent's safety rules, library writes, what is sent
where, the build and CI, and the tests and docs that hold them to their promises.
[`.github/protected-paths.txt`](.github/protected-paths.txt) lists these frozen paths. A pull request
that changes one fails the "protected paths" check. For those parts, open an issue that describes the
problem, with your idea for a fix if you have one. Ideas that harden the design are especially welcome.

## What belongs here

lit-fetch-ladder covers finding and fetching papers, up to filing a batch into Zotero. Requests about
the library after that (search, reading, citing, annotating) belong to
[Zotero MCP](https://github.com/54yyyu/zotero-mcp). Filing stays limited to adding items, attaching
files, writing a note and trashing the plugin's own filings.

## Opening an issue

- **A bug.** Use the bug report form. Paste the doctor's output after removing your email and your
  library's proxy address.
- **A publisher that does not download.** Use the "publisher does not download" form. Give the DOI and
  the publisher, never your proxy address or a link copied from a logged-in page, because such links can
  carry your session.
- **An idea or a change you would like.** Open a blank issue and describe it, or open a pull request if
  it stays outside the frozen paths.
- **A way past the guard.** Report it privately, as described in [SECURITY.md](SECURITY.md), not in a
  public issue.

## Running the tests

Clone the repository and run:

```
node --test tests/*.test.mjs tests/redteam/*.test.mjs   # guard, sign-in, launcher, red-team replay
python3 -m unittest discover -s tests                     # rungs 0-1, the manifest and filing, offline
claude plugin validate --strict .                         # manifests, hooks, MCP servers, skills
```

The Python tests need only the standard library. CI runs the tests on every pull request and push to
main, with Python 3.9 and Node 18 and with the newest Python and Node LTS, and the plugin check on the
newest. A change outside the frozen paths that
changes behaviour comes with a test in `tests/test_tools.py`.

To try your own copy in Claude Code, add the clone as a marketplace with
`/plugin marketplace add <path to your clone>` and install the plugin from it. Claude Code reads hooks
at start, so restart it after changing `hooks/hooks.json`. The README's figures are generated by
`docs/assets/make_figures.py`.

## How the guard is changed

Only the author changes the guard (`guard/guard.mjs`), and these are the rules an idea for it is held
to. Each change comes with a test in `tests/guard.test.mjs` that fails before it and passes after, keeps
the red-team replay in `tests/redteam/` passing, and never raises the page-load limits or removes a
check. An entry in `guard/known-sites.json` widens what one approval covers: a known redirect is added
only when seen in a real run, and a click site only for a publisher's own journal platform. The Python
tools have no dependencies, and the plugin pins one npm package, `@playwright/mcp`.
